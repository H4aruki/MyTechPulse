# サーバー側認証セッションを採用する

2026-09-14、ブラウザの `localStorage` にJWTを保存する方式から、HttpOnly Cookieで不透明なセッションIDを渡す方式へ移行すると決めた。XSS時にJavaScriptから認証情報を読み取られる範囲を減らし、ログアウトや期限切れをサーバー側で確実に失効できるようにするためである。DBにはセッションIDのSHA-256ハッシュだけを保存し、Cookie認証に伴うCSRFはOrigin検査と専用ヘッダーで防ぐ。

旧JWTは引き継がず、Go版切り替え時に利用者へ一度だけ再ログインしてもらう。既存のbcryptパスワードはそのまま検証し、再登録やパスワード初期化は求めない。
