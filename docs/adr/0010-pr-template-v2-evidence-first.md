# PRテンプレート v2 は、証拠と図を先に見せる

- 状態: 採用（2026-11-13）。[PR #300](https://github.com/H4aruki/MyTechPulse/pull/300) でマージ済み
- 日付: 2026-11-13
- 決定者: Haruki。AIは起案者
- 全体の概要: [0004](0004-automerge-small-prs-by-deterministic-script.md)

## 背景と問題

PRを人が理解してマージするまでの時間が、いまのボトルネックである。AIの出力を信頼できるものにすれば、人は本質的な判断だけでよくなる、というのが目標だった。そのためには、PRの本文が、差分を全部読まなくても判断できる形である必要がある。

## 検討した案

| 案 | 内容 | 採否 | 採らなかった理由（採用なら採った理由） |
|---|---|---|---|
| A | 一行で → なぜ → 理解しておいてほしい1点 → 確かめたこと → 判断が必要なこと → 見てほしい場所 | 採用 | Harukiさんの指定。証拠を見たあとに判断するため |
| B | 「判断が必要なこと」を先頭にする | 不採用 | 証拠の後に判断する順にする（Harukiさん指定の順） |
| C | 文章中心 | 不採用 | 人の認知負荷・理解負荷を下げるため、図と画像を先に置く |
| D | 「直した」という自己申告で足りる | 不採用 | poteto: 直す前に落ちるテストと通るテスト、before / after を見せる。自己申告では通さない |

## 決定

節の順番: 一行で → なぜ → 理解しておいてほしい1点 → 確かめたこと → 判断が必要なこと（「なし」以外は自動マージ対象外）→ 見てほしい場所 → 確認（秘密情報、本番・DB・認証）。

### 図・証拠の規則

- 図か画像を先に置く。挙動は mermaid（flowchart か sequence）、状態は状態図、画面は before / after のスクショ、操作は短い動画。
- 図の直後に、その図が示すことを1文で書く。図だけ、説明だけは不可。
- 動く部分が3つ以上ある流れは、1枚に足し込まず、短いシリーズにする（まず A→B、次に C を足す）。
- スクショは実際の画面。モックや想像図は「参考」と明示する。
- 無いときは「なし」と理由を1行書く。空欄は不可。
- 秘密情報・個人情報・本番の値が写っていたら出さない。
- 証拠は、AIの自己申告ではなく、テスト・スクショ・ボットの判定コメントが正。ボットのコメントは、PRごとに1つ（pushのたびに上書き）。

## 理由（判断基準）

1. 人が頭の中で組み立てなくてもよいこと（認知負荷・理解負荷を下げる）。
2. 証拠を見たあとに判断すること。
3. 自己申告ではなく、検証の成果物（テスト、スクショ、図、ボットの判定）を正とすること。

## 結果と代償

- 良くなること: 判定コメントと「判断が必要なこと」を先に見れば、クラスAで判断事項が「なし」のPRは、差分を読まなくてよい。
- 代償: PRを書く側（AI）の手間が増える。図やスクショを用意しなければならない。
- 残るリスク: 図や証拠が形だけになる。そのため、判定はボットのコメントを正とし、本文の自己申告だけでは通さない。
