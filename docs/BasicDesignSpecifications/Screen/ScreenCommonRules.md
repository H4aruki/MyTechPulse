# 画面に共通する決まりごと

すべての画面に共通する取り決めをまとめたもの。画面ごとの詳しい中身は[ScreenList.md](ScreenList.md)から各詳細ファイルをたどる。

## 1. スマホ・タブレット優先という方針

MyTechPulseは「通勤時間や寝る前の隙間時間に、手軽に技術情報を収集できること」を売りにする。そのため画面はスマホ・タブレットでの利用を主に想定して作り、パソコンはそれに次ぐ扱いとする。

- 要件定義書の非機能要件には「パソコンでの利用を主に想定しており、専用のスマホアプリはない」とあるが、これは方針転換により実態と合わなくなっている。要件定義書側は別途更新する
- 「専用のスマホアプリを作らない」という前提は変わらない。あくまでブラウザで開いたときにスマホ・タブレットで使いやすい見た目にする、という話

## 2. ブレークポイント

画面の幅によってレイアウトを切り替える境目は、次の3段階とする。基準を1つに揃えることで、画面ごとに境目がバラバラになるのを防ぐ。

| 名前 | 幅の目安 | 想定する端末 |
| --- | --- | --- |
| 基準（指定なし） | 〜639px | スマホ |
| sm | 640px〜 | 大きめのスマホ・小さいタブレット |
| md | 768px〜 | タブレット |
| lg | 1024px〜 | パソコン |

- 「基準（指定なし）」の見た目を最初に決め、画面が広がるにつれて`sm` → `md` → `lg`の順に上書きしていく考え方（モバイルファースト）で統一する
- 数値は実装で使っているTailwind CSSの既定値にそのまま合わせている。独自の値を新しく作らない

## 3. 共通のレイアウト構成

| 部品 | 内容 |
| --- | --- |
| ヘッダー | ロゴ（トップまたは記事一覧へのリンクを兼ねる）、Qiita・Zennへの外部リンク、右側に操作ボタン（未ログイン時: 新規登録・ログイン／ログイン中: ログアウト）。画面上部に固定しスクロールに追従する |
| フッター | サービス名・作成者のクレジット |

- G-02（会員登録）・G-03（ログイン）・G-04（記事一覧）はこの共通ヘッダー・フッターを1つの部品（`frontend/src/components/AppLayout.tsx`）から使う
- G-01（LP）だけは検索エンジンにインデックスさせるためReactを使わない静的HTMLで作っており、見た目は共通ヘッダーに似せつつ独立した実装になっている。両者が見た目上ズレないよう、デザインを変えるときはLPとSPA側の両方に反映する
- G-01のヘッダーには、上記に加えてページ内リンク（機能・仕組み・対応ソース）が入る。`md`未満ではハンバーガーメニューに収納する

## 4. 入力チェックの共通ルール（G-02・G-03）

| ルール | 内容 |
| --- | --- |
| 空入力の禁止 | ユーザー名・パスワードが未入力のまま送信できない。送信を押した時点でその場に知らせる |
| チェックのタイミング | ブラウザ側（フロントエンド）で送信前にチェックする。サーバー側のエラーとは別に扱う |
| 送信中の見た目 | 送信ボタンを押している間は再度押せないようにし、ボタンの文言を「登録中…」「ログイン中…」に変える |

## 5. エラー表示の見た目に関する決まり

文言そのもの（「利用者名またはパスワードが違います」等）はAPI側の資料（`docs/BasicDesignSpecifications/API/`）でまとめて定義する。ここで決めるのは、エラーが起きたときに**どこに・どんな形で出すか**という見た目のルールだけ。

| 種類 | 出す場所 | 見た目 |
| --- | --- | --- |
| 入力項目ごとのエラー（例: 未入力） | その入力欄のすぐ下 | 赤色の文字。欄の枠色は変えない |
| 送信結果のエラー（例: 利用者名の重複、認証失敗） | フォームの下部、送信ボタンより上 | 薄い赤色の背景＋赤色の文字の帯 |
| 一覧の取得失敗（G-04） | 一覧が表示される場所そのもの | 薄い赤色の背景の枠内にエラー内容と「再読み込み」ボタン |
| 学習の送信失敗（クリック時の興味の更新） | 表示しない | F-5-4のとおり、記事の閲覧を妨げないためエラーを画面に出さない |

- どの場合も、エラー表示は該当箇所の近くに置き、画面全体を覆うような表示（モーダル等）は使わない
- スマホでの見やすさを優先し、エラー文言は折り返して全文表示する（省略しない）

## 6. 状態ごとの見え方の共通ルール

| 状態 | 見た目 |
| --- | --- |
| 読み込み中 | 対象箇所に「読み込んでいます…」等の文言を表示する。スピナー等の追加装飾は必須としない |
| データが0件 | 「対象がありません」の旨を、一覧が表示されるはずだった場所にそのまま表示する |
| 通信失敗 | 上記5.のエラー表示に従う |
