# 画面詳細: G-02 会員登録画面

[画面一覧に戻る](../ScreenList.md) ／ 共通の取り決めは[画面に共通する決まりごと](../ScreenCommonRules.md)を参照

利用者名・パスワードの入力と興味タグの選択を経て、新しい利用者を登録する画面。

| 項目 | 内容 |
| --- | --- |
| 実装場所 | `frontend/src/pages/SignupPage.tsx` |
| ログイン | 不要 |
| 呼び出す窓口 | A-2-1 会員登録（[Auth.md](../../API/Details/Auth.md)） |
| 対応する機能 | F-2-1（会員登録）、F-2-2（利用者名の重複チェック）、F-2-3（パスワードの保護）、F-2-9（入力内容のチェック）、F-3-1〜F-3-4（興味タグ関連） |

## 1. 構成

1画面の中で2ステップに分かれる。ページ遷移はせず、同じ画面の中身が切り替わる。

### ステップ1: アカウント情報

| 表示項目 | 内容 |
| --- | --- |
| 見出し | 「新規登録」 |
| 入力欄 | ユーザー名、パスワード |
| ボタン | 「次へ：興味のあるタグを選ぶ」 |
| 案内リンク | 「すでにアカウントをお持ちの方は ログイン」→ G-03へ |

### ステップ2: 興味タグの選択

| 表示項目 | 内容 |
| --- | --- |
| 見出し | 「興味のあるタグを選択してください」＋補足文（1つ以上選ぶ旨） |
| タグ一覧 | カテゴリ（言語／フレームワーク等）ごとに見出しとタグの選択肢が並ぶ |
| カテゴリ見出し | チェックボックス付き。そのカテゴリ内のタグを一括選択・解除できる |
| ボタン | 「戻る」（ステップ1に戻る）、「登録する（◯件選択中）」 |

## 2. 入力項目と入力チェック

| 項目 | 必須 | チェック内容 |
| --- | --- | --- |
| ユーザー名 | ○ | 未入力ならステップ1から次へ進めず、欄の下にエラーを出す |
| パスワード | ○ | 同上 |
| 興味タグ | ○（1つ以上） | 0件のままだと「登録する」ボタンを押せない（非活性） |

- 入力したパスワードは画面上に一時保存されるだけで、ブラウザのストレージ等には保存しない
- 送信（登録）は、ステップ2で「登録する」を押した時点で、ユーザー名・パスワード・選択済みタグをまとめて1回のAPI呼び出しで送る

## 3. 状態ごとの見え方

| 状態 | 見た目 |
| --- | --- |
| 送信中 | 「登録する」ボタンが押せなくなり、文言が「登録中…」に変わる |
| 登録成功 | そのままログイン状態になり、G-04（記事一覧）へ遷移する |
| 登録失敗（重複・サーバーエラー等） | ステップ1に戻り、フォーム下部にエラーを表示する（[画面共通の決まりごと](../ScreenCommonRules.md#5-エラー表示の見た目に関する決まり)の「送信結果のエラー」に従う） |

## 4. レスポンシブの扱い

- フォームの最大幅を絞り、スマホでは画面幅いっぱいに広がる1カラム表示にする
- タグの選択肢は折り返し表示（幅が足りなければ次の行へ）で、カテゴリごとの一括選択チェックも含めてどの幅でも操作できるようにする
- ステップ2の「戻る」「登録する」ボタンは画面下部に固定表示し、タグが多くて縦に長くなってもスクロールせず押せるようにする（スマホでの片手操作を想定）

## 5. 補足

- 現状はタグの一覧がフロントエンドに直接書かれており、バックエンドの`tag`テーブルとの二重管理になっている。動的取得への切り替えは別課題として検討中
