# 画面詳細: G-04 記事一覧画面

[画面一覧に戻る](../ScreenList.md) ／ 共通の取り決めは[画面に共通する決まりごと](../ScreenCommonRules.md)を参照

利用者の興味に合わせてQiita・Zennから集めた記事を表示する、ログイン後のメイン画面。通勤時間や隙間時間に開いてもらうことを想定した、サービスの中心となる画面。

| 項目 | 内容 |
| --- | --- |
| 実装場所 | `frontend/src/pages/ArticlesPage.tsx` |
| ログイン | 必要（合言葉が無いとG-03へ自動的に戻される） |
| 呼び出す窓口 | A-4-1 おすすめ記事の取得、A-5-1 記事クリックの記録（[News.md](../../API/Details/News.md) / [Article.md](../../API/Details/Article.md)） |
| 対応する機能 | F-4-1〜F-4-9（記事の配信）、F-5-1〜F-5-4（興味の学習） |

## 1. 構成

| 表示項目 | 内容 |
| --- | --- |
| 見出し | 「あなたにおすすめの記事」 |
| Qiitaセクション | 見出し「Qiita Articles」＋記事カードの一覧（最大10件） |
| Zennセクション | 見出し「Zenn Articles」＋記事カードの一覧（最大10件） |
| ヘッダー | 共通ヘッダー＋ログアウトボタン（[画面共通の決まりごと](../ScreenCommonRules.md#3-共通のレイアウト構成)を参照） |

### 記事カード1件ごとの表示項目

| 項目 | 内容 |
| --- | --- |
| タイトル | 記事のタイトル |
| 提供元 | Qiita／Zenn |
| 反響数 | いいね数（♥アイコン付き） |
| 公開日 | 日本語表記の日付 |
| タグ | 記事に付いているタグを複数表示 |

## 2. 操作と遷移

| 操作 | 動き |
| --- | --- |
| 記事カードをクリック | 記事の元ページを新しいタブで開く。同時に、その記事のタグをサーバーへ送って興味の学習に使う（F-5-1） |
| 「再読み込み」ボタン（失敗時のみ表示） | 記事の再取得をやり直す |
| ヘッダーの「ログアウト」 | ブラウザに保存した合言葉を消し、G-03（ログイン画面）へ戻る |

- 記事クリックによる学習の送信は失敗しても画面上に何も表示しない（F-5-4）。記事を新しいタブで開く動作自体は学習の成否に関わらず必ず行う

## 3. 状態ごとの見え方

| 状態 | 見た目 |
| --- | --- |
| 読み込み中 | 「記事を読み込んでいます…」を画面中央に表示する |
| 取得失敗 | エラー内容と「再読み込み」ボタンを表示する（[画面共通の決まりごと](../ScreenCommonRules.md#5-エラー表示の見た目に関する決まり)の「一覧の取得失敗」に従う） |
| Qiita・Zennそれぞれが0件 | 該当セクションに「おすすめの記事はまだありません。」を表示する。セクション単位で判定するため、片方が0件でももう片方は通常どおり表示する |

- 記事の再取得は、タブを再度アクティブにしただけでは走らない（外部APIへの問い合わせ回数を抑えるため）。一定時間（5分）が経つか、明示的に再読み込みしたときのみ取得し直す

## 4. レスポンシブの扱い

- 記事カードの一覧は、スマホ幅（`sm`未満）では1カラム、`sm`以上では2カラムで並べる
- カード内の項目（提供元・反響数・公開日）は折り返し表示にし、幅が狭くても情報が見切れないようにする
- 通勤中の片手操作を想定し、カード全体をタップ領域にする（タイトルやアイコンなど一部だけをタップ対象にしない）
