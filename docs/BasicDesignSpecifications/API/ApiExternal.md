# 外部サービスへの問い合わせ

サーバーが記事を集めるために呼び出している、外部（Qiita・Zenn）の窓口をまとめたもの。ここは自分たちが提供する窓口ではなく、相手先の仕様に合わせて呼び出している部分になる。

呼び出しが起きるのは[おすすめ記事の取得（A-4-1）](Details/News.md)のときだけ。

## 1. 問い合わせ先の一覧

| 提供元 | 方式・アドレス | 主な条件 | 認証 |
| --- | --- | --- | --- |
| Qiita | GET `https://qiita.com/api/v2/tags/{タグ名}/items` | 1ページ目・20件 | 利用登録して発行した鍵を`.env`に置き、見出しに付けて送る |
| Zenn | GET `https://zenn.dev/api/articles` | タグ名（小文字）で絞り込み・5件 | 不要 |

## 2. 呼び出し方

- 興味の強さが大きい上位5つのタグについて、QiitaとZennの両方へまとめて同時に問い合わせる
- 1回の記事一覧表示あたり、外部への問い合わせは最大10回（5タグ × 2提供元）
- 順番に待たず同時に投げるため、待ち時間は「一番遅い1回」に近い長さで済む

## 3. 気をつけている点

| 点 | 内容 |
| --- | --- |
| タグ名の変換 | タグ名をアドレスに埋め込む前に必ず変換してから送る。記号を含むタグでも、意図しない別の窓口へ届いてしまわないようにするため |
| 大文字・小文字 | Zennは小文字でないと記事が見つからないため、送る前に小文字へそろえる |
| タグ情報の補い | Zennの一覧には記事本来のタグが含まれないため、「どのタグで検索して見つかったか」をその記事のタグとして扱う。複数のタグで見つかった記事は1件にまとめる |
| 失敗したとき | 問い合わせが失敗した場合は、そのタグ分だけ0件として扱い、画面全体は止めない |

## 4. 補足

- Qiitaの鍵は`backend/.env`に置き、リポジトリには含めない
- 問い合わせが部分的に失敗すると、気づかないまま特定の分野の記事だけが減ることがある。この扱いの見直しは検討中の課題として残している
- 記事をあらかじめ集めておく方式に変えれば、この問い合わせは利用者の画面表示とは切り離せる（機能一覧のF-4-10）
