# API詳細: 記事クリックの記録

[API一覧に戻る](../ApiList.md) ／ 共通の取り決めは[APIの共通の決まりごと](../ApiCommonRules.md)を参照

## A-5-1 記事クリックの記録

利用者がクリックした記事のタグを受け取り、興味の強さを更新する。次回以降のおすすめに反映するための窓口。

| 項目 | 内容 |
| --- | --- |
| 方式・パス | POST `/api/v1/feedback/article-clicks` |
| 本人確認 | 必要（Cookie） |
| 対応する機能 | F-5-1（クリックした記事の記録）、F-5-2（興味の強さの更新）、F-5-3（新しいタグの追加） |

書き込み操作のため、共通の決まりごとのとおり、許可されたサイトからの送信と`X-MTP-CSRF: 1`ヘッダーが必要。

### 送るもの

| 項目名 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| tags | 文字列の配列 | ○ | クリックされた記事に付いていたタグ。1〜50件、各1〜50文字 |

記事そのもの（タイトルやアドレス）は送らない。学習に使うのはタグだけのため。

### 返るもの

| ステータス | code | 意味 |
| --- | --- | --- |
| 204 | ― | 更新できた。返す本文はない |
| 401 | `unauthenticated` | ログインしていない、またはセッションの期限切れ |
| 422 | `validation_failed` | タグの件数や文字数が決まりに合わない |
| 500 | `internal_error` | 更新に失敗した。書き込みはすべて元に戻す |

### 興味の強さの更新のしかた

1. その利用者が持っている全タグの興味を0.8倍に弱める
2. クリックした記事のタグにだけ0.2を足す（上限は1）
3. 結果を保存する

古い興味が少しずつ薄れ、最近読んだ分野が強まる。積み重なることで、直近の関心に寄せたおすすめになる。

- 送られたタグが、その利用者にまだ無かった場合は、その場で新しく登録して、0.2を初期値として学習の対象に加える
- 同じ記事のタグに、大文字・小文字や前後の空白だけが違うものが混ざっていても、1つとして数える（足すのは1回だけ）
- 興味の強さは0〜1の小数だが、保存するときは1万倍した整数に変換している（[データベース構成](../../DataBaseArchitecture.md)を参照）。小数のままだと誤差が出るため、サーバー内部でも整数のまま計算している（0.8倍は「×8÷10」、0.2は2000）
- 更新は、その利用者の行を先にロックしてから行う。同時に複数のクリックが届いても、値が食い違わない

### 補足

- 画面側は記事を新しいタブで開くのと同時にこの窓口を呼ぶ。結果を待たずに記事へ進むため、利用者を待たせることはない
- 失敗しても画面にはエラーを出さず、記事の閲覧は妨げない。学習が1回抜けるだけで、次のクリックで取り返せるため
- 旧版（Python）にあった「本文の`status`で0/1を返す」決まりは、なくなった。成否はHTTPステータスで見る
