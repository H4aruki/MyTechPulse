# API詳細: 会員登録・ログイン

[API一覧に戻る](../ApiList.md) ／ 共通の取り決めは[APIの共通の決まりごと](../ApiCommonRules.md)を参照

利用者の登録と本人確認を扱う2つの窓口。どちらも成功したときだけ、期限付きの合言葉を返す。

## 1. A-2-1 会員登録

利用者名・パスワード・興味のあるタグを受け取り、利用者を新しく登録する。

| 項目 | 内容 |
| --- | --- |
| 方式・パス | POST `/auth/create_user` |
| 本人確認 | 不要 |
| 対応する機能 | F-2-1（会員登録）、F-2-2（利用者名の重複チェック）、F-3-4（興味の強さの保存） |

### 送るもの

| 項目名 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| newusername | 文字列 | ○ | 新しく使う利用者名 |
| newpassword | 文字列 | ○ | パスワード。元に戻せない形に変換してから保存する |
| favoritetags | 文字列の配列 | ○ | 選んだ興味タグの名前 |

### 返るもの

| 項目名 | 型 | 説明 |
| --- | --- | --- |
| status | 数値 | 結果（下表） |
| access_token | 文字列 または 空 | 成功時のみ入る期限付きの合言葉 |

| status | 意味 | 合言葉 | 画面の動き |
| --- | --- | --- | --- |
| 1 | 登録成功 | あり | そのままログイン状態になり記事一覧へ進む |
| 2 | その利用者名はすでに使われている | 空 | 画面に重複を知らせる |
| 0 | 保存の途中で失敗した | 空 | 途中まで書き込んだ内容はすべて取り消される |

### 補足

- 利用者・タグ・興味の強さという3か所へまとめて書き込むため、どこかで失敗した場合はすべて元に戻す
- 選ばれたタグがまだ登録されていなければ、その場で新しく追加する
- 利用者名の重複はデータベース側でも重ねて防いでいる（[データベース構成](../../DataBaseArchitecture.md)を参照）

## 2. A-2-2 ログイン

利用者名とパスワードで本人確認を行う。

| 項目 | 内容 |
| --- | --- |
| 方式・パス | POST `/auth/login_check` |
| 本人確認 | 不要 |
| 対応する機能 | F-2-4（ログイン）、F-2-5（ログイン失敗時の表示） |

### 送るもの

| 項目名 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| username | 文字列 | ○ | 利用者名 |
| password | 文字列 | ○ | パスワード |

### 返るもの

| 項目名 | 型 | 説明 |
| --- | --- | --- |
| status | 数値 | 結果（下表） |
| access_token | 文字列 または 空 | 成功時のみ入る期限付きの合言葉 |

| status | 意味 | 合言葉 |
| --- | --- | --- |
| 1 | ログイン成功 | あり |
| 2 | 本人確認に失敗 | 空 |

### 補足

- 「その利用者名が存在しない」場合と「パスワードが違う」場合を区別せず、同じ値・同じ文言を返す。どの利用者名が登録済みかを外部から推測されないようにするため
- 保存されているのは元に戻せない形に変換したパスワードなので、入力された文字列を同じ方法で変換して照合している
