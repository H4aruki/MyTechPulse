# API詳細: 会員登録・ログイン・ログアウト・パスキー

[API一覧に戻る](../ApiList.md) ／ 共通の取り決めは[APIの共通の決まりごと](../ApiCommonRules.md)を参照

利用者の登録と本人確認を扱う窓口（A-2-1〜A-2-4）と、パスキーの窓口（A-2-5〜A-2-11）。会員登録とログイン（パスワード・パスキーのどちらも）に成功したときだけ、セッションのCookieを発行する（本文には合言葉を含めない）。

書き込み操作（POST）には、共通の決まりごとのとおり、許可されたサイトからの送信と`X-MTP-CSRF: 1`ヘッダーが必要。

## 1. A-2-1 会員登録

利用者名・パスワード・興味のあるタグを受け取り、利用者を新しく登録して、そのままログイン状態にする。

| 項目 | 内容 |
| --- | --- |
| 方式・パス | POST `/api/v1/auth/signup` |
| 本人確認 | 不要 |
| 対応する機能 | F-2-1（会員登録）、F-2-2（利用者名の重複チェック）、F-3-4（興味の強さの保存） |

### 送るもの

| 項目名 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| username | 文字列 | ○ | 新しく使う利用者名。前後の空白を除いて1〜50文字 |
| password | 文字列 | ○ | パスワード。1文字以上、UTF-8で72バイト以内。元に戻せない形に変換してから保存する |
| favorite_tags | 文字列の配列 | ○ | 選んだ興味タグ。1〜128件、各タグは前後の空白を除いて1〜50文字。大文字・小文字を区別せず、重複は1つにまとめる |

### 返るもの

| ステータス | code | 意味 | 本文・Cookie |
| --- | --- | --- | --- |
| 201 | ― | 登録成功。そのままログイン状態になる | 本文`{"user": {"id", "username", "role"}}`と、セッションのCookie |
| 409 | `username_taken` | その利用者名はすでに使われている | エラー本文のみ |
| 422 | `validation_failed` | 入力が決まりに合わない | `errors`に項目ごとの指摘 |
| 500 | `internal_error` | サーバー内部の失敗 | エラー本文のみ。途中まで書き込んだ内容はすべて取り消される |

利用者（`user`）の項目は次のとおり。

| 項目名 | 型 | 説明 |
| --- | --- | --- |
| id | 数値 | 利用者ID |
| username | 文字列 | 利用者名 |
| role | 文字列 | 役割。`member`（一般の利用者）または`admin`。登録した時点では必ず`member` |

### 補足

- 利用者・タグ・興味の強さ・最初のセッションという4か所へ**1回のまとまりで**書き込む。どこかで失敗した場合はすべて元に戻る
- 選ばれたタグがまだ登録されていなければ、その場で追加する。表記だけが違うタグ（大文字・小文字、前後の空白）は、同じタグとして扱い、重複して作らない
- 利用者名の重複は、データベース側の制約でも重ねて防いでいる（[データベース構成](../../DataBaseArchitecture.md)を参照）
- パスワードの変換は、元に戻せない方式（bcrypt）で行い、強さの設定は旧版と同じにそろえてある。そのため、Python版の時代に登録した利用者もそのままログインできる

## 2. A-2-2 ログイン

利用者名とパスワードで本人確認を行い、セッションのCookieを発行する。

| 項目 | 内容 |
| --- | --- |
| 方式・パス | POST `/api/v1/auth/login` |
| 本人確認 | 不要 |
| 対応する機能 | F-2-4（ログイン）、F-2-5（ログイン失敗時の表示）、F-2-6（本人確認） |

### 送るもの

| 項目名 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| username | 文字列 | ○ | 利用者名 |
| password | 文字列 | ○ | パスワード |

### 返るもの

| ステータス | code | 意味 | 本文・Cookie |
| --- | --- | --- | --- |
| 200 | ― | ログイン成功 | 本文`{"user": {...}}`と、セッションのCookie |
| 401 | `invalid_credentials` | 利用者名またはパスワードが違う | エラー本文のみ |
| 422 | `validation_failed` | 入力が決まりに合わない（空など） | `errors`に項目ごとの指摘 |
| 500 | `internal_error` | サーバー内部の失敗 | エラー本文のみ |

### 補足

- 「その利用者名が存在しない」場合と「パスワードが違う」場合を区別せず、**同じ401・同じ文言**を返す。どの利用者名が登録済みかを外部から推測されないようにするため
- 利用者が存在しない場合も、見せかけの照合を1回行い、処理時間の差から存在を推測されにくくしている
- ログインのたびに新しいセッションを作る。同時に別の端末でログインしても、互いのセッションは別々に有効
- ログインのついでに、期限が切れたセッションをデータベースから掃除する。掃除に失敗してもログインは止めない

## 3. A-2-3 ログイン中の利用者の確認

セッションのCookieが有効かどうかを確かめ、ログイン中の利用者を返す。画面側は、画面を開いたときにこれを呼んで、ログイン済みかどうかを判断する。

| 項目 | 内容 |
| --- | --- |
| 方式・パス | GET `/api/v1/auth/me` |
| 本人確認 | 必要（Cookie） |
| 対応する機能 | F-2-6（本人確認）、F-2-7（ログインが必要な画面の保護） |
| 送るもの | なし |

### 返るもの

| ステータス | code | 意味 | 本文 |
| --- | --- | --- | --- |
| 200 | ― | ログイン中 | `{"id", "username", "role"}` |
| 401 | `unauthenticated` | ログインしていない、または期限切れ | エラー本文 |
| 500 | `internal_error` | サーバー内部の失敗 | エラー本文 |

## 4. A-2-4 ログアウト

現在のセッションだけをサーバー側で失効させ、Cookieを破棄する。

| 項目 | 内容 |
| --- | --- |
| 方式・パス | POST `/api/v1/auth/logout` |
| 本人確認 | 不要（Cookieがあれば、そのセッションを失効する） |
| 対応する機能 | F-2-8（ログアウト） |
| 送るもの | なし |

### 返るもの

| ステータス | 意味 |
| --- | --- |
| 204 | ログアウト完了。Cookieを破棄する指示を返す |
| 500 | サーバー内部の失敗。セッションが残っている可能性がある |

### 補足

- すでにセッションが無い、または期限が切れている場合も、成功（204）として扱う。何度呼んでも同じ結果になる
- 他の端末のセッションは失効しない。失効するのは、この端末のセッションだけ
- 500のときは、画面側が「ログアウトに失敗した」と知らせ、利用者がもう一度試せるようにしている

## 5. A-2-5 パスキー登録の開始

端末（スマートフォンやセキュリティキー）へ渡す、パスキー登録の設定を返す。

| 項目 | 内容 |
| --- | --- |
| 方式・パス | POST `/api/v1/auth/passkeys/register/begin` |
| 本人確認 | 必要（Cookie） |
| 送るもの | なし |

| ステータス | code | 意味 | 本文・Cookie |
| --- | --- | --- | --- |
| 200 | ― | 開始成功 | 本文`{"publicKey": {...}}`と、手続きを結び付ける短命のCookie（HttpOnly・5分） |
| 401 | `unauthenticated` | ログインしていない | エラー本文のみ |
| 409 | `passkey_limit_reached` | 登録数が上限（1人10件）に達している | エラー本文のみ |

- 手続きの印（チャレンジ）は5分で切れ、1回しか使えない
- 登録済みのパスキーは除外の一覧に入れ、同じ端末の二重登録を防ぐ。端末の本人確認と、利用者名なしで選べるパスキーを必須にする

## 6. A-2-6 パスキー登録の完了

端末の応答を検証して保存する。手続きの印は、成功・失敗にかかわらずここで使い切る。

| 項目 | 内容 |
| --- | --- |
| 方式・パス | POST `/api/v1/auth/passkeys/register/finish` |
| 本人確認 | 必要（Cookie） |

| 項目名 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| name | 文字列 |  | パスキーの名前。前後の空白を除いて1〜64文字。省略すると「パスキー」 |
| credential | オブジェクト | ○ | 端末が返した登録の結果 |

| ステータス | code | 意味 |
| --- | --- | --- |
| 201 | ― | 登録成功。本文は`{"id", "name", "created_at"}`。公開鍵や認証情報IDは返さない |
| 400 | `passkey_challenge_invalid` | 手続きが無い・期限切れ・使用済み・他の利用者のもの |
| 400 | `passkey_verification_failed` | 端末の応答を検証できない |
| 401 | `unauthenticated` | ログインしていない |
| 409 | `passkey_already_registered` / `passkey_limit_reached` | すでに登録済み / 上限に達している |
| 422 | `validation_failed` | 名前が決まりに合わない |

## 7. A-2-7 パスキーの一覧

自分のパスキーだけを、登録順に返す。

| 項目 | 内容 |
| --- | --- |
| 方式・パス | GET `/api/v1/auth/passkeys` |
| 本人確認 | 必要（Cookie） |

200のとき、本文は`{"passkeys": [{"id", "name", "created_at", "last_used_at"}]}`。まだ使っていないパスキーは`last_used_at`を省略する。ログインしていなければ401（`unauthenticated`）。

## 8. A-2-8 パスキーの名前変更

| 項目 | 内容 |
| --- | --- |
| 方式・パス | PATCH `/api/v1/auth/passkeys/{id}` |
| 本人確認 | 必要（Cookie） |
| 送るもの | `name`（前後の空白を除いて1〜64文字） |

成功は204。他の利用者のパスキーと、存在しないパスキーは区別せず、同じ404（`not_found`）を返す。名前が決まりに合わないときは422、ログインしていなければ401。

## 9. A-2-9 パスキーの削除

| 項目 | 内容 |
| --- | --- |
| 方式・パス | DELETE `/api/v1/auth/passkeys/{id}` |
| 本人確認 | 必要（Cookie） |

自分のパスキーだけを物理削除する。成功は204。他の利用者のものと存在しないものは、同じ404（`not_found`）を返す。パスワードの再入力は求めない。

## 10. A-2-10 パスキーでのログインの開始

利用者名を入力せずに、端末に保存されたパスキーを選ばせるための設定を返す。

| 項目 | 内容 |
| --- | --- |
| 方式・パス | POST `/api/v1/auth/passkeys/login/begin` |
| 本人確認 | 不要 |
| 送るもの | なし |

| ステータス | code | 意味 | 本文・Cookie |
| --- | --- | --- | --- |
| 200 | ― | 開始成功 | 本文`{"publicKey": {...}}`（`allowCredentials`は空）と、手続きを結び付ける短命のCookie（HttpOnly・5分） |
| 429 | `too_many_requests` | この接続元IPが締め出し中、または開始の回数が上限 | `Retry-After`（秒） |

- 手続きの印は5分で切れ、1回しか使えない。開始のたびに、期限切れの印を掃除する
- 開始は、ログインの失敗としては数えない（正規の利用者を締め出さないため）。締め出し中のIPには429を返す
- 開始そのものも、接続元IPごとに数える（未ログインで呼べて、呼ぶたびにDBへ書くため）。最初の開始から15分の間に60回までで、超えた分は429と`Retry-After`（秒）を返し、印は保存しない。失敗の数え方とは別の枠なので、使い切っても、完了の失敗の枠やパスワードのログインには影響しない（逆も同じ）。成功・失敗で数は戻らず、窓が終われば数え直す

## 11. A-2-11 パスキーでのログインの完了

端末の応答を検証し、成功すればパスワードのログインと同じ属性のセッションCookieを発行する。

| 項目 | 内容 |
| --- | --- |
| 方式・パス | POST `/api/v1/auth/passkeys/login/finish` |
| 本人確認 | 不要 |
| 送るもの | `credential`（端末が返したログインの結果）と、開始で受け取ったCookie |

| ステータス | code | 意味 | 本文・Cookie |
| --- | --- | --- | --- |
| 200 | ― | ログイン成功 | 本文`{"user": {...}}`と、セッションのCookie。手続きのCookieは破棄する |
| 401 | `invalid_credentials` | ログインできなかった | エラー本文のみ |
| 422 | `validation_failed` | 本文の形が決まりに合わない（`credential`が無い・オブジェクトでない） | `errors`に項目ごとの指摘 |
| 429 | `too_many_requests` | この接続元IPが締め出し中 | `Retry-After`（秒）。手続きの印は使い切らない |
| 500 | `internal_error` | サーバー内部の失敗（DB障害など） | エラー本文のみ |

### 補足

- 手続きの印は、検証の成功・失敗にかかわらず1回で使い切る
- 次の失敗はすべて、本文までバイト単位で同じ401にする。原因から、パスキーの登録の有無や仕組みを探られないようにするため: 手続きの印が無い・偽・期限切れ・使用済み・登録用の印、未知のパスキー、他の利用者の識別子への差し替え、署名やオリジンや本人確認の不一致、認証回数の巻き戻り（複製の疑い）、登録時から変わった同期の設定
- 認証回数は、保存した値より増えていなければ拒否する。ただし、同期パスキーのように0を返し続ける端末（保存0・受信0）は許す。巻き戻りを見つけたときは、利用者のIDとパスキーのIDだけをログに残す
- 失敗は、接続元IPごとに数える。パスワードのログインと同じ窓（15分に20回失敗で、窓が終わるまで）を共有するので、合算して数える。利用者名の窓には触れない。成功しても、IPの失敗の数は戻らない。DB障害（500）と、本文の形の不正（422）は数えない
- パスキーのログインに成功しても、利用者名ごとのパスワードの締め出しは解除しない。パスワードで締め出された本人は、パスキーなら入れる
- ログインのたびに新しいセッションを作る（古いセッションは失効しない）。パスワードのログインと同じ手順で、期限切れのセッションを掃除する
