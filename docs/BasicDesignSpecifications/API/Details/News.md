# API詳細: おすすめ記事の取得

[API一覧に戻る](../ApiList.md) ／ 共通の取り決めは[APIの共通の決まりごと](../ApiCommonRules.md)を参照

## A-4-1 おすすめ記事の取得

合言葉から利用者を特定し、その人の興味に合う記事をQiita・Zennから集めて返す。このアプリの中心となる窓口。

| 項目 | 内容 |
| --- | --- |
| 方式・パス | POST `/news/personal_news` |
| 本人確認 | 必要（`Authorization: Bearer <合言葉>`） |
| 対応する機能 | F-4-1〜F-4-4（記事の取得・絞り込み・並べ替え・提供元ごとの表示）、F-4-7（Zennが0件のときの補完） |
| 送るもの | なし（誰の記事かは合言葉から判断する） |

### 返るもの

| 項目名 | 型 | 説明 |
| --- | --- | --- |
| status | 数値 | 1＝記事が1件以上ある、0＝両方とも0件 |
| qiita_articles | 記事の配列 | Qiitaの記事。点数の高い順に最大10件 |
| zenn_articles | 記事の配列 | Zennの記事。点数の高い順に最大10件 |

### 記事1件の中身

| 項目名 | 型 | 説明 |
| --- | --- | --- |
| title | 文字列 | 記事のタイトル |
| url | 文字列 | 記事のアドレス |
| source | 文字列 | 提供元（`Qiita` または `Zenn`） |
| tags | 文字列の配列 | 記事に付いているタグ |
| likes | 数値 | 反響の数。Zennは「いいね」の数を入れる |
| published_at | 文字列 | 公開日（YYYY-MM-DD） |

QiitaとZennで返ってくる形は違うが、サーバー側でこの同じ形に整えてから返している。画面側は提供元を意識せず同じ書き方で表示できる。

### 内部の流れ

1. 興味の強さが大きい上位5つのタグを選ぶ
2. そのタグごとにQiitaとZennへ同時に問い合わせる（[外部サービスへの問い合わせ](../ApiExternal.md)を参照）
3. Qiitaは直近5日以内、Zennは直近2週間以内の記事に絞る
4. 「興味の強さの合計」と「反響の大きさ」から点数を付けて並べ替える
5. 提供元ごとに上位10件ずつ返す

### 点数の付け方

| 提供元 | 点数 |
| --- | --- |
| Qiita | 記事に付いたタグの興味の強さの合計 × （いいね数＋1） |
| Zenn | 記事に付いたタグの興味の強さの合計のみ |

Zennは取得の時点で提供元側の人気順に絞られているため、反響の数を重ねて掛けると人気の記事ばかりが並ぶ。そのため興味の強さだけで並べている。

### 記事が集まらなかったときの動き

| 状況 | 動き |
| --- | --- |
| 興味タグを1つも持っていない | 両方とも0件（status＝0）で返す。外部への問い合わせは行わない |
| Zennの記事が1件も残らなかった | 問い合わせを増やさずに、すでに取得した結果から期間の条件だけを外して埋め合わせる |
| Qiita・Zennの両方が0件 | status＝0で返し、画面側は「記事が見つからない」と表示する |

### 補足

- 記事はデータベースに保存しておらず、この窓口が呼ばれるたびに外部へ取りに行く。そのため表示までの待ち時間は外部サービスの応答速度に左右される
- あらかじめ記事を集めておいて表示を速くする案は未実装（機能一覧のF-4-10）。進捗はリポジトリ直下の`TASKS.md`で管理している
- タグを突き合わせるときは大文字・小文字の違いを無視して比べている
