# API詳細: おすすめ記事の取得

[API一覧に戻る](../ApiList.md) ／ 共通の取り決めは[APIの共通の決まりごと](../ApiCommonRules.md)を参照

## A-4-1 おすすめ記事の取得

ログイン中の利用者の興味に合う記事をQiita・Zennから集めて返す。このアプリの中心となる窓口。

| 項目 | 内容 |
| --- | --- |
| 方式・パス | GET `/api/v1/feed` |
| 本人確認 | 必要（Cookie） |
| 対応する機能 | F-4-1〜F-4-4（記事の取得・絞り込み・並べ替え・提供元ごとの表示）、F-4-7（Zennが0件のときの補完） |
| 送るもの | なし（誰の記事かはセッションから判断する） |

### 返るもの

| ステータス | code | 意味 |
| --- | --- | --- |
| 200 | ― | 成功。片方の提供元だけ失敗した場合や、記事が0件の場合も200で返す（下の`warnings`で区別する） |
| 401 | `unauthenticated` | ログインしていない、またはセッションの期限切れ |
| 503 | `providers_unavailable` | QiitaとZennの**両方**が使えず、1件も取得できなかった |
| 500 | `internal_error` | サーバー内部の失敗 |

200の本文は次の3項目。

| 項目名 | 型 | 説明 |
| --- | --- | --- |
| qiita_articles | 記事の配列 | Qiitaの記事。点数の高い順に最大10件。該当なしなら空の配列 |
| zenn_articles | 記事の配列 | Zennの記事。点数の高い順に最大10件。該当なしなら空の配列 |
| warnings | 知らせの配列 | 取得に失敗した提供元の知らせ。すべて成功したときは空の配列 |

### 記事1件の中身

| 項目名 | 型 | 説明 |
| --- | --- | --- |
| title | 文字列 | 記事のタイトル |
| url | 文字列 | 記事のアドレス（`https://qiita.com/…`または`https://zenn.dev/…`のみ） |
| source | 文字列 | 提供元（`Qiita` または `Zenn`） |
| tags | 文字列の配列 | 記事に付いているタグ。Zennは、検索に使ったタグだけが入る |
| likes | 数値 | 反響の数（いいね数） |
| published_at | 文字列 | 公開日時（ISO 8601の日時。例: `2026-10-07T01:23:45Z`） |

QiitaとZennで返ってくる形は違うが、サーバー側でこの同じ形に整えてから返している。画面側は提供元を意識せず同じ書き方で表示できる。

### 取得に失敗した提供元の知らせ（warnings）

| 項目名 | 型 | 説明 |
| --- | --- | --- |
| provider | 文字列 | 失敗した提供元（`qiita` または `zenn`） |
| code | 文字列 | 失敗の種類。現在は`provider_unavailable`のみ |

- 片方だけ失敗した場合は、もう片方の記事を返したうえで、失敗した側を`warnings`に入れる。画面側は「一部の記事を取得できませんでした」と知らせる
- 一部のタグだけ失敗した場合も、その提供元は`warnings`に入る。取れた分の記事は返す
- 提供元が返した記事の形が想定と違った（必須項目が無い、アドレスが想定外など）場合も、取得失敗として扱う

### 内部の流れ

1. 興味の強さが大きい上位5つのタグを選ぶ（同じ強さなら小文字にそろえた名前の順）
2. そのタグごとにQiitaとZennへ同時に問い合わせる（[外部サービスへの問い合わせ](../ApiExternal.md)を参照）。全体で8秒を超えたら打ち切る
3. Qiitaは直近5日以内、Zennは直近14日以内の記事に絞る
4. 同じ記事（同じアドレス）は1件にまとめ、タグを合わせる
5. 利用者が持つ**すべて**の興味タグを使って点数を付け、並べ替える
6. 提供元ごとに上位10件ずつ返す

### 点数の付け方

| 提供元 | 点数 |
| --- | --- |
| Qiita | 記事に付いたタグの興味の強さの合計 × （いいね数＋1） |
| Zenn | 記事に付いたタグの興味の強さの合計のみ |

- 点数が同じときは、新しい記事、提供元名、アドレスの順で決め、毎回同じ並びになるようにしている
- Zennは取得の時点で提供元側の人気順に絞られているため、反響の数を重ねて掛けると人気の記事ばかりが並ぶ。そのため興味の強さだけで並べている
- タグを突き合わせるときは、前後の空白を除いて、大文字・小文字の違いを無視して比べている

### 記事が集まらなかったときの動き

| 状況 | 動き |
| --- | --- |
| 興味タグを1つも持っていない | 問い合わせは行わず、両方とも空の配列で200を返す |
| Zennの記事が14日以内に1件も残らなかった | 問い合わせを増やさずに、すでに取得した結果から期間の条件だけを外して埋め合わせる |
| Qiita・Zennの両方が0件（失敗ではない） | 両方とも空の配列で200を返す。画面側は「おすすめの記事はまだありません。」と表示する |
| 両方の提供元が失敗した | 503（`providers_unavailable`）を返す。画面側は再読み込みを案内する |

### 補足

- 記事はデータベースに保存しておらず、この窓口が呼ばれるたびに外部へ取りに行く。そのため表示までの待ち時間は外部サービスの応答速度に左右される
- あらかじめ記事を集めておいて表示を速くする案は未実装（機能一覧のF-4-10）。進捗はリポジトリ直下の`TASKS.md`で管理している
- 同じ利用者の過去の閲覧は、記事のデータとしては保存していない。保存しているのはタグごとの興味の強さだけ
- 旧版（Python）にあった「本文の`status`で0/1を返す」決まりは、なくなった。成否はHTTPステータスで見る
