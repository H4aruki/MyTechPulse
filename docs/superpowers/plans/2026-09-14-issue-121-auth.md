# Issue 121 Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 既存bcryptハッシュをそのまま検証し、サーバー側セッションCookieで登録・ログイン・現在利用者取得・ログアウトを安全に提供する。

**Architecture:** `internal/auth` に型・用途・インターフェースを置き、PostgreSQL実装とHTTP実装を外側へ分離する。ブラウザには乱数トークンだけを渡し、DBにはSHA-256ハッシュだけを保存する。

**Tech Stack:** Go 1.26、Huma v2.39.1、pgx v5.11.0、sqlc v1.31.1、golang.org/x/crypto v0.57.0、PostgreSQL 17

**Spec:** `docs/superpowers/specs/2026-09-14-go-backend-migration-design.md`

## Global Constraints

- 既存 `user.password` のbcryptハッシュを再生成・一括更新しない
- パスワード、Cookie値、セッショントークン、DB接続情報をログへ出さない
- 利用者不存在と誤パスワードは同じHTTP 401 Problem Detailsにする
- `role` は `member` と `admin` だけを許可し、登録時は常に `member` にする
- 本番Cookieは `__Host-mtp_session`、local/testは `mtp_session` とし、Path `/`、HttpOnly、SameSite=Lax、本番Secureとする
- 状態変更は許可Originと `X-MTP-CSRF: 1` の両方を要求する
- ログアウトはCookieやDB行が無くても204にする
- 管理者画面・管理者APIはこのIssueで作らない
- signupおよびタグ関連実装の開始条件は、Issue #119のタグ衝突監査が完了済みであること
- 開始前に`ops/sql/audit_tag_collisions.sql`を実行し、結果が0件かつ終了コードが0であることを確認する
- タグ衝突がある、または監査を実行・判定できない場合は、signupおよびタグ関連実装を開始しない
- 衝突したタグは自動で統合せず、人間がデータ修正方針を判断する

- [ ] **Step 1: Python生成済みbcryptとの互換テストを書く**

- [ ] **Step 2: 32byte乱数、URL-safe表現、SHA-256保存値をテストする**

```go
func TestTokenGeneratorReturnsPlainAndHash(t *testing.T) {
    plain, hash, err := (RandomTokenGenerator{}).New()
    if err != nil { t.Fatal(err) }
    raw, err := base64.RawURLEncoding.DecodeString(plain)
    if err != nil || len(raw) != 32 { t.Fatal("invalid token") }
    if sha256.Sum256([]byte(plain)) != hash { t.Fatal("hash mismatch") }
}
```

- [ ] **Step 3: 最小実装を書く**

`BcryptPasswords.Hash` は1文字以上かつ72byte以内のUTF-8パスワードだけを `bcrypt.GenerateFromPassword` へ渡し、costは現行Passlibと同じ12へ固定する。生成hashのcostが12であるtestも追加する。`Compare` は入力異常を認証失敗として扱う。`RandomTokenGenerator.New` は `crypto/rand.Read` で32byteを生成し、`base64.RawURLEncoding` で平文を作り、その文字列をSHA-256へ通す。

- [ ] **Step 1: query契約の結合テストを書く**

- [ ] **Step 2: SQLを書く**

```sql
-- name: FindUserByUsername :one
SELECT "user_ID", user_name, password, role FROM "user" WHERE user_name = $1;
-- name: CreateUser :one
INSERT INTO "user" (user_name, password, role) VALUES ($1, $2, $3)
RETURNING "user_ID", user_name, role;
-- name: CreateSession :exec
INSERT INTO auth_session (token_hash, "user_ID", expires_at) VALUES ($1, $2, $3);
-- name: FindSessionUser :one
SELECT u."user_ID", u.user_name, u.role, s.expires_at
FROM auth_session s JOIN "user" u ON u."user_ID" = s."user_ID"
WHERE s.token_hash = $1 AND s.expires_at > $2;
-- name: DeleteSession :exec
DELETE FROM auth_session WHERE token_hash = $1;
-- name: DeleteExpiredSessions :exec
DELETE FROM auth_session WHERE expires_at <= $1;
```

`signup.sql` には正規化タグ検索、tag作成、`match_int=1` のrecommend作成を置く。tagごとに `SELECT pg_advisory_xact_lock(hashtext('tag:' || $1))` を取得してから `lower(btrim(tag_name))` で再検索し、Go書き込み同士の表記違い重複を防ぐ。

```sql
-- name: LockNormalizedTag :exec
SELECT pg_advisory_xact_lock(hashtext('tag:' || $1));
-- name: FindTagByNormalizedName :one
SELECT "tag_ID", tag_name FROM tag
WHERE lower(btrim(tag_name)) = $1 ORDER BY "tag_ID" LIMIT 1;
-- name: CreateTag :one
INSERT INTO tag (tag_name) VALUES ($1) RETURNING "tag_ID", tag_name;
-- name: CreateInitialRecommendation :exec
INSERT INTO recommend ("user_ID", "tag_ID", match_int) VALUES ($1, $2, 1);
```
