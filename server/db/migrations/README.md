## 追加だけの決まり

本番の自動デプロイは、DBの移行を入れ替えより先に行い、入れ替えに失敗すると直前のAPIへ戻る。DBは巻き戻さないため、直前のAPIが、移行後のDBでも動く必要がある。そのため、移行（`-- +goose Up`）は**追加だけ**にする。

- してよい: 表・列・索引の追加、既定値のあるNOT NULLの列の追加、新しい列への制約の追加、データの追加。
- してはいけない: DROP（表・列・制約。索引だけは可）、RENAME、TRUNCATE、DELETE FROM、列の型の変更、既存の列をNOT NULLにする、既定値の無いNOT NULLの列の追加。
- 列を消す・名前を変えるときは、「新しい列を足す → 新旧どちらも動く版を出す → 古い列を使わなくなってから消す」の順に、複数回の更新に分ける。
- この決まりは `additive_test.go` が機械的に確認する（CIの「Goバックエンドの検査」で動く）。どうしても破壊的な変更が要るときは、自動デプロイに乗せず、手順を決めて、オーナーの承認のもとで行う。そのときは、この試験の変更について、承認を得る。
